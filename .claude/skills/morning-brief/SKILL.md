# Morning brief

The first thing the household sees each day. It succeeds when it says something
they did not already know, and fails when it reads like a calendar printout.

## Read first

`memory/facts.md`, `memory/open-loops.md`, `memory/misses.md`, and the tail of
yesterday's `memory/daily/` file — specifically the "tomorrow's setup" note the
evening review left.

## Structure

Lead with the thing most likely to go wrong today. Not the first event
chronologically — the one that needs attention. Then:

- **Today, per person.** Only what is theirs. Times adjusted for what you have
  learned about this household's real clock, not the times on the calendar.
- **Needs a decision today.** Anything that must be answered now to avoid a
  problem later — an RSVP, a booking that fills up, a form due.
- **Quiet open loops.** Anything promised and untouched for over a week. One
  line, no nagging tone.
- **Worth knowing.** Weather only if it changes plans. Traffic only if it
  changes departure. Nothing that is merely true.

## Rules

- **Short.** Read on a phone, half awake. If it takes more than thirty seconds
  it will stop being read, and an unread brief is worse than none.
- **Never pad.** A quiet day gets three lines. Do not manufacture content to
  justify the routine.
- **Be specific.** "Leave by 8:40 to make the 9:00" beats "don't forget school."
  Names, times, numbers.
- **Never invent.** If the calendar is thin, the day is thin. Say so.
- **Flag your own uncertainty.** "I think Maya has practice — never confirmed"
  is more useful than a confident wrong claim, and it prompts the correction
  that makes you right tomorrow.
