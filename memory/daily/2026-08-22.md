## What this actually proves

The scheduler is not the hard part; it worked first time. The hard part is that a
scheduled run is only as useful as the credentials and write access it inherits,
and it inherits far less than the session that created it. A heartbeat that can
think but cannot read the mail or commit what it learned is a demo, not a system.

- The brief was run manually and **delivered by email** at 07:25 EDT: subject
  "Hearth — morning brief, Sat 22 Aug", preflight lines first, then the brief.
  That is the correct delivery surface and it should stay that way: it lands
  somewhere findable, identifiable, and permanent, unlike a push notification or
  an unlisted transcript.

## What today actually established

Delivery by email is right. The scheduler works. The gap is only *where the
scheduled run lives*, and there are exactly three options, one of which is not
in Hearth's hands:

1. Bound to an existing session — full tools, but dies with the session.
2. Fresh session via this tool — no connectors, therefore useless.
3. **Created by Jeffery in the claude.ai Routines UI**, where connector grants
   are available to him even though the API refuses them here. Most likely the
   durable answer, and the only one Hearth cannot do for itself.
